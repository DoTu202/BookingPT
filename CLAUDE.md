# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BookingPT — a mobile app connecting freelance Personal Trainers (PT) with clients (search PTs, book sessions, chat, notifications). Two independent npm projects, no root package.json:

- `clients/` — React Native 0.79 app (JS/JSX with some TS), Redux Toolkit, React Navigation 7
- `server/` — Node.js 20 + Express 5 REST API, MongoDB via Mongoose 8, JWT auth, bcrypt

## Commands

Server (run from `server/`, needs `server/.env` — copy `.env.example`; `MONGODB_URI` and `JWT_SECRET` are required, the app throws on startup otherwise):
- `npm run dev` — nodemon, port `PORT` (default 3001)
- `npm test` — Jest + Supertest against mongodb-memory-server (no external DB needed). Single file: `npx jest tests/booking.test.js`; single test: `npx jest -t "only one of many concurrent"`. If a local `mongod` exists, `MONGOMS_SYSTEM_BINARY=$(which mongod)` avoids the binary download.
- `npm run lint` — ESLint 9 flat config (`server/eslint.config.js`).
- `npm run test-accounts` — non-destructive: creates/resets the client + PT accounts whose credentials are `TEST_CLIENT_*` / `TEST_PT_*` in `server/.env` (and tops up the PT's open slots). Use this against shared DBs instead of `seed`.
- `npm run seed` — wipes the DB in `MONGODB_URI` and inserts demo data (accounts `client@demo.com` / `pt@demo.com`, password `Password123!`). Refuses to run with `NODE_ENV=production`.
- `docker compose up --build` (repo root) — API + MongoDB.
- CI: `.github/workflows/ci.yml` runs server lint + tests + `npm audit`, and client lint + unit tests.

Client (run from `clients/`):
- `npm start` (Metro), `npm run ios` / `npm run android`
- `npm run lint` — ESLint config lives in `clients/.eslintrc.js`; `react-hooks/exhaustive-deps` is a warning by design.
- `npm test` — Jest unit tests in `__tests__/` (pure logic: validators, time utils, reducer). Rendering full screens in Jest is not set up (navigation ESM packages aren't transformed).
- iOS pods: `bundle install && cd ios && bundle exec pod install`

API URL: `clients/src/constants/appInfos.js` — in `__DEV__` it uses `localhost` (iOS sim) / `10.0.2.2` (Android emu) unless `DEV_API_URL_OVERRIDE` is set (needed for physical devices); release builds use `PROD_API_URL` (must be HTTPS).

## Server architecture

`index.js` (connect DB, listen, graceful shutdown) → `src/app.js` (Express app, exported for tests). Middleware order in `app.js`: helmet → CORS (native apps have no Origin) → `express.json({limit:'100kb'})` → `sanitizeInput` (strips `$`/`.` keys from body/params; Express 5's query parser doesn't build nested objects) → rate limiters → routers → `notFound` → `errorHandler`.

- Config: all env access goes through `src/configs/env.js` (`MONGODB_URI`, `JWT_SECRET`, `MAIL_USER`/`MAIL_PASSWORD`, ...; see `.env.example`). Indexes declared in the models are built by Mongoose on connect.
- Logging: pino (`src/configs/logger.js`) + pino-http in `app.js` (request id echoed as `X-Request-Id`; one short line per request — `METHOD url status time` — logged at `debug` for 2xx/3xx, `warn` for 4xx, `error` for 5xx, so the default `info` level only shows failures; headers aren't logged). In handlers use `req.log`, elsewhere `logger`; no `console.*` in `src/` (lint warns).
- Layers: routers → thin controllers (read/validate input, shape the response) → `src/services/*` (business logic, no `req`/`res`). Response shapes are relied on by the app — don't rename or remove fields, only add.
- Errors: controllers are wrapped in `express-async-handler`; throw the helpers from `src/utils/httpError.js` (`badRequest`, `forbidden`, `notFound`, `conflict`, ...) — they carry `.statusCode`, so they also work inside services. `errorHandler` maps CastError/ValidationError/11000/Multer errors and hides 5xx details + stack in production. Don't send `error.message` from catch blocks directly.
- Input: shared validators/constants (`str`, `normalizeEmail`, `assertEmail`, `assertPassword`, `assertPhone`, `parseDob`, `optionalText`, `BCRYPT_ROUNDS`, `MIN_PASSWORD_LENGTH`) live in `src/utils/validators.js`. Ids from params/body must be checked with `assertValidId(value, name)` (`src/utils/helpers.js`) — malformed ids should be 400, not 500. User text used in `$regex` must go through `escapeRegex`; pagination via `parsePagination` (caps page size at 50); "a day" filters via `dayRange()` which interprets dates in `Asia/Ho_Chi_Minh` and returns UTC bounds.
- Auth: `src/services/tokenService.js` signs `{id, role}` (HS256). `authMiddleware` loads the user, rejects inactive users and tokens with `iat` older than `user.passwordChangedAt` (password change/reset revokes old tokens; change-password returns a fresh token). `User.password` is `select: false` — use `.select('+password')` when comparing.
- Token revocation: `authMiddleware` rejects tokens whose `iat` is older than `max(passwordChangedAt, tokensValidAfter)`; `POST /api/profile/logout-all` sets `tokensValidAfter`.
- Sign-up / password reset / email change use server-side OTPs (`src/services/otpService.js`, `OtpModel` with TTL index): codes are hashed, 10-min expiry, 5 attempts, 60s resend cooldown, and are **never returned in API responses**. `/auth/register` requires the `code`. Email changes go through `/api/profile/email/request` + `/confirm` (OTP bound to the requesting `userId`); `PUT /api/profile/profile` rejects a changed email.
- Mail: `src/services/mailService.js`; falls back to a JSON (no-send) transport when SMTP vars are missing or in tests. Tests mock `sendOtpMail` to capture codes.
- Bookings: `src/services/bookingService.js` is the only place a booking's status changes (the state diagram is at the top of the file). Every transition is a conditional `findOneAndUpdate` with the expected status and time rules in the filter (`applyTransition`), so concurrent requests can't both win; on no match it reloads to return 404/403/400, or 409 if another request got there first. Flow: `pending_confirmation` → `confirmed` / `rejected_by_pt` / `cancelled_by_client` / `rejected_by_system`; `confirmed` → `completed` / `cancelled_by_client` (≥24h notice) / `cancelled_by_pt` (`POST /api/pt/bookings/:id/cancel`, `reason` required). Client cancel and PT reject accept an optional `reason`; all three store `cancellationReason` + `cancelledAt`.
- Booking/slot invariant: creating a booking atomically flips the `Availability` slot `available → booked` (`findOneAndUpdate` with `status: 'available'` in the filter) — this is what prevents double booking. Reject/client cancel/expiry set it back to `available`; PT cancel sets it to `unavailable_by_pt` (editing that slot re-opens it). Booked slots can't be edited or deleted.
- Realtime (Socket.IO, `src/services/realtimeService.js`, attached to the HTTP server in `index.js`): push-only. Clients connect with `auth: {token}` (checked by `userFromToken` from `authMiddleware`, same rules as REST) and join `user:<id>`; services push with `emitToUsers(userIds, event, payload)` (no-op when not initialized, e.g. supertest tests). Writes stay on REST: `chatService.sendMessage` stores the message and emits `chat:message` `{chatRoomId, message, clientId?}` to both members; `chat:typing` is relayed client→other member after a membership check. Call `disconnectUser(userId)` wherever tokens are revoked (password change/reset, logout-all, account deletion). Socket tests: `tests/realtime.test.js` (real server on port 0 + `socket.io-client`). Behind a reverse proxy, WebSocket upgrades must be allowed.
- Notifications: create them through `notifySafely(params, req.log)` in `src/services/notificationService.js` — failures are logged, never fail the action. It also sends a push (title per type in `PUSH_TITLES`).
- Push (FCM, `src/services/pushService.js`): optional — disabled unless `FIREBASE_SERVICE_ACCOUNT` (JSON or path to the service-account file) is set; always off in tests unless a fake is installed with `setPushTransport(fn)` (see `tests/push.test.js`). Devices register via `POST/DELETE /api/profile/push-token` (`DeviceToken` model, token unique, moves to the last user who registers it). `sendPush(userIds, {title, body, data})` never throws and isn't awaited by callers; data values are stringified; tokens FCM reports as unregistered are deleted. Pushes: every notification (`type: 'notification'`) and every chat message to the recipient (`type: 'chat'`, sender fields for the app to open the chat). Call `removeUserDeviceTokens(userId)` next to `disconnectUser` wherever tokens are revoked.
- Background jobs: `src/services/bookingMaintenance.js` (started from `index.js` every 5 min, not in tests) runs `expireStaleBookings` (unanswered requests past their start → `rejected_by_system`), `sendBookingReminders` (`booking_reminder` to both sides within 24h of a confirmed session, once, tracked by `reminderSentAt`) and `autoCompleteBookings` (confirmed sessions that ended 12h+ ago → `completed`). Each claims a booking with a conditional update, so they're safe on several instances. In tests call the jobs directly with an optional `now`.
- PT dashboard: `GET /api/pt/dashboard?period=week|month|year&offset=N` → `src/services/dashboardService.js#getPtDashboard(ptId, {period, offset, now})` (aggregations only; weeks start Monday, buckets via `$dateToString` in `Asia/Ho_Chi_Minh`). Sessions count in the period of their start time; earnings = completed `priceAtBooking`; `attention` (pending / confirmed-but-ended) is about now, not the period. Tests pass a fixed `now` (`tests/dashboard.test.js`).
- Reviews: `ReviewModel` (one per completed booking, by its client). `PTProfile.rating`/`numReviews` are derived — always update them through `refreshPtRating(ptId)` in `src/services/reviewService.js`, never set them directly (the seed does the same).
- Data exposure: other users' email/phone/dob are not returned in public PT endpoints (`PUBLIC_PT_USER_FIELDS` in `clientController`); PTs do see their own clients' email in bookings.
- Uploads: multer writes to `server/uploads/profiles` (git-ignored); file extension comes from a MIME allow-list, never from the client filename. `photoUrl` is built from `PUBLIC_URL` or the request host. After multer saves a file, `utils/imageSignature.js` checks its magic bytes against the claimed type.

## Client architecture

- `App.tsx` → `SafeAreaProvider` → Redux `Provider` → `NavigationContainer` → `navigators/AppRouter.jsx`, which restores `auth` from AsyncStorage, shows `SplashScreen`, then `AuthNavigator` (no `accesstoken`) or `MainNavigator`.
- `MainNavigator` branches on `auth.role`: `'pt'` → `PTTabNavigator`; otherwise `DrawerNavigator` (drawer wrapping `ClientTabNavigator`, drawer screen name `ClientTabNavigator`). Shared stack screens (Chat, Notifications, EditProfile, ChangePassword) are registered in both branches — add new shared screens to both.
- Session: Redux is the source of truth for the token. AsyncStorage key `auth` holds a copy only when "Remember me" is on. Always sign out via `utils/session.js#signOut(dispatch)` (clears both).
- API layer: every request goes through `src/apis/axiosClient.js`, which reads the token from the Redux store, signs the user out on 401, and rethrows an `Error` with `.status` and `.response` attached. Its message is already Vietnamese: server messages go through `translateServerMessage` (`utils/errorMessage.js` — add new server messages there) and network failures get a friendly text. Show `error.message` in UI; never `error.response.data.message`. Per-domain modules (`authApi`, `clientApi`, `ptApi`, `chatApi`, `notificationApi`, `profileApi`); some keep an unused token argument for backwards compatibility.
- Dates: import dayjs from `utils/dayjs.js` (registers utc/timezone/customParseFormat), never from `'dayjs'` directly — Metro's inline requires mean a plugin registered in another module may not be loaded yet (`utcOffset(420).format` crashed when a screen rendered before `timeUtils` was used). Server sends UTC ISO strings; display/input conversion to Vietnam time lives in `utils/timeUtils.js`. Build `YYYY-MM-DD` strings with `dayjs(date).format(...)`, never `toISOString().split('T')[0]` (that's the UTC day).
- Password rules are shared: `MIN_PASSWORD_LENGTH` in `utils/validate.js` must match the server (`src/utils/validators.js`).
- UI language is Vietnamese. Labels for API codes (booking statuses, specializations) live in `constants/labels.js`; money/location/duration formatting in `utils/format.js` (`formatCurrency` → `350.000 ₫`); times are shown 24h via `timeUtils.formatTo24HourTime`.
- Design system: tokens in `constants/appColors.js` (prefer semantic names: `background`, `surface`, `border`, `textMuted`, `*Soft`; gradients `gradientPrimary` / `gradientDark`) and `constants/theme.js` (`spacing`, `radius`, `shadow`, `TOUCH_TARGET` = 48, `header` = shared radius/icon-button size of the gradient headers). There are no background images: `AppBackground` draws the brand backdrop (splash, auth) with gradients + SVG glows. Gradients: always `GradientView` (SVG-based). `react-native-linear-gradient` was removed — under the New Architecture it ran through the interop layer and drew inset when it had padding/children (white band under the notch); don't add it back. Headers: fixed screens use `ScreenHeader` (gradient header, safe area/status bar, `onBack` / `left` / `right` slots + `HeaderIconButton`); screens that open on a scrolling hero (homes, profiles) use `HeroScrollView` (collapsing header): pass the hero as `hero` (it draws the status-bar strip above it, so the hero uses no `insets.top`) and `title` / `subtitle` / `left` / `right` for the compact `ScreenHeader` that pins once the hero scrolls away. Other shared pieces in `src/components`: `ProfileHero` (profile hero with avatar upload, inside `HeroScrollView`), `StateView` (loading / empty / error + retry — use it for screen content; there is no blocking loading modal), `ButtonComponent` (`type` primary|secondary|outline|danger|ghost|link, `size`, `isLoading`), `InputComponent` (`label`, `error`, `helperText`, `prefix`, forwards `ref`; `isPassword` owns `secureTextEntry`), `Avatar` (initial fallback), `ChipComponent`, `StatusBadge`, `StatCard`, `MenuList`, `DateStrip` (VN-time day picker, `todayKey()`, optional `marks` dots), `SegmentedControl`, `BarChart` (View-based, tap to select a bar), `RingProgress` (SVG), `BookingCard`, `PtItem` (+ `toPtItem(profile)`), `ModernTabBar` (used by both tab navigators; icons via `navigators/tabIcon.js`).
- Realtime: `src/apis/socketClient.js` — `MainNavigator` opens one socket per session via `useRealtimeConnection(auth.accesstoken)` (closes on sign-out/token change, reconnects when the app returns to foreground). Screens listen with `useSocketEvent(event, handler)`; the `'connect'` pseudo-event fires on every (re)connect so screens refetch what they missed. Chat no longer polls: `ChatScreen` merges socket messages by `_id` and drops the optimistic bubble whose `tempId` comes back as `clientId`.
- Push: `utils/pushNotifications.js` (`@react-native-firebase/messaging`, modular API). No-op until Firebase is configured natively: `ios/Project/GoogleService-Info.plist` (AppDelegate only calls `FirebaseApp.configure()` when it exists) and `android/app/google-services.json` (the gradle plugin is applied only when it exists); iOS also needs the Push Notifications capability (`aps-environment`) and the APNs key uploaded to Firebase. `MainNavigator` calls `usePushNotifications(auth.accesstoken)` (permission, token registration, tap → `ChatScreen` / `Notifications` via `navigators/navigationRef.js#navigateWhenReady`); `signOut()` unregisters the device first. Notifications aren't shown in the foreground (the socket updates the UI). iOS pods: Firebase needs static frameworks — the Podfile sets `use_frameworks! :linkage => :static`, `$RNFirebaseAsStaticFramework` and `$RNFirebaseDisableSPM`; keep them.
- Session updates (new name/photo/token) go through `utils/session.js#updateSession(dispatch, auth, patch)` so the "Remember me" copy stays in sync; profile photos via `utils/photoUpload.js#pickAndUploadProfilePhoto`. Reason/review prompts: `modals/ReasonModal`, `modals/ReviewModal` (cross-platform; `Alert.prompt` is iOS-only). Auth screens share `screens/auth/components/AuthLayout`. Poppins via `constants/fontFamilies.js`. SVGs import as components (`react-native-svg-transformer`).
- PT dashboard: `PTDashboardScreen` (stack route `PTDashboard`, PT branch only; opened from the PT home stat cards / "Thống kê" quick action). Labels/percentages live in `utils/dashboard.js` (unit-tested). `PTHomeScreen` takes its month numbers and "needs attention" counts from the same endpoint and only loads today's bookings.
- The bottom tab bars are not absolutely positioned, so screens don't need extra bottom padding for them.
